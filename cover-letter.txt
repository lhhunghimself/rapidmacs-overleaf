Dear Editors,

We submit "RapidMACS: MACS3-identical peak calling, 50x faster" for
consideration as an Applications Note in the Genome analysis section.

MACS has been the standard narrow peak caller for chromatin assays for nearly
two decades, and remains the caller that Signac, ArchR, SnapATAC2 and SCENIC+
invoke, and that ENCODE's ATAC-seq and transcription-factor peak sets are
built from. Many pipelines, including ours in the MorPhiC consortium, use
exactly one of its fourteen subcommands: narrow peak calling. RapidMACS is a
C++ reimplementation of that one path, written from MACS3's published
description rather than ported from its code.

The claim that distinguishes it from other fast peak callers is not that it
agrees closely with MACS3, but that its output is byte-identical to MACS3
v3.0.3: every narrowPeak and summit field, and the full-file MD5 sums, across
single-cell ATAC-seq, bulk ATAC-seq, ChIP-seq and CUT&RUN, on fragment and
BAMPE input, with and without a matched control. Anything computed downstream
therefore returns exactly what it would have returned from MACS3, so the
substitution can be made part-way through an established analysis without
putting earlier comparisons in question. It is 3.5 to 51 times faster
depending on assay, input format and thread count, and the gains come from
specialisation rather than language choice, since MACS3's peak-calling code is
itself compiled Cython.

We think this fits an Applications Note rather than a research paper: the
contribution is a tool and its exact equivalence, not a new statistical
method. The peak-calling statistics are MACS3's.

Everything needed to check the claims is public. The source is MIT-licensed at
https://github.com/morphic-bio/rapidmacs, released as v1.0.1, with
multi-architecture containers on Docker Hub. The repository includes the
complete benchmark matrix, every recorded measurement with per-run checksums,
and a script that downloads a public dataset, runs both callers, and exits
non-zero unless the output matches the published checksums.

A preprint of this work is posted on bioRxiv.
